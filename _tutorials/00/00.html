Working on a Challenge

Before writing a single line of ggplot2, you need to know where your files are and how R finds them. This tutorial explains files, folders and the working directory in plain terms, and gives you a step-by-step routine to follow for every challenge: create a project, put the data in it, write your script, test it, and submit it.

0. Before you start

Your computer is not your phone. On a phone, apps hide files from you. On a computer, every file lives in a specific place, and you need to know that place to use the file.

This tutorial explains the few ideas you need, then gives you a routine you repeat for every challenge. Follow the steps in order, every time. After two or three challenges you won’t need this tutorial.

By the end of the course, your computer will look like this:

Documents/
└── DataViz/
    ├── challenge-00/
    │   ├── challenge-00.Rproj
    │   ├── data.RData
    │   ├── challenge-00.R
    │   └── output.png
    ├── challenge-01/
    │   ├── challenge-01.Rproj
    │   ├── data.RData
    │   ├── challenge-01.R
    │   └── output.png
    └── ...

One folder for the course. Inside it, one folder per challenge. Inside each challenge folder, everything for that challenge.

1. Five ideas you need (and nothing more)

1.1 Files and folders

A file is a document: a photo, a script, a dataset. A folder is a drawer that holds files and other folders. Folders can be inside folders, like drawers inside drawers.

1.2 File extensions

The letters after the last dot in a file name tell you what kind of file it is:

Extension What it is In this course
.RData Data saved by R The data you download (data.RData)
.R An R script (your code) What you write and upload
.png An image The plot your script creates (output.png)
.Rproj An RStudio project The file you double-click to start working

Windows and macOS hide extensions by default. You will turn them on in Section 2.2.

1.3 Paths: the address of a file

A path is the address of a file: the list of folders you open to reach it. For example:

  • Windows: C:\Users\anna\Documents\DataViz\challenge-01\data.RData
  • macOS: /Users/anna/Documents/DataViz/challenge-01/data.RData

You will almost never type a path. You need to know that it exists, because every file has one.

1.4 The working directory: where R is standing

R is always “standing” inside one folder. This folder is called the working directory. When your script says:

load("data.RData")

R looks for data.RData only in the folder where it is standing. If the file is somewhere else, for example in Downloads, R will not find it, even though it’s on your computer.

The golden rule: data.RData, your script, and the place where R is standing must all be the same folder.

1.5 RStudio Projects: a folder that tells R where to stand

An RStudio Project is a normal folder with a .Rproj file inside. When you open a project, RStudio makes R stand in that folder automatically. That’s why we use one project per challenge. Open the project, and R is already in the right place.

2. One-time setup (do this once, at the start of the course)

2.1 Create your course folder

Create a folder called DataViz inside your Documents folder.

Windows

  1. Open File Explorer (the yellow folder icon in the taskbar, or press Windows key + E).
  2. Click Documents in the left sidebar.
  3. Right-click an empty area → New → Folder.
  4. Type DataViz and press Enter.

macOS

  1. Open Finder (the blue face icon in the Dock).
  2. Click Documents in the left sidebar.
  3. Right-click an empty area → New Folder.
  4. Type DataViz and press Return.

Naming rule for everything in this course: no spaces, no accents, no special characters. Use challenge-01, not Challenge 1 or reto nº1.

OneDrive and iCloud: on many computers, the Documents folder is synced to the cloud: OneDrive on Windows, iCloud Drive on macOS. Then the path of your files may include OneDrive or iCloud Drive (for example, C:\Users\anna\OneDrive\Documents\DataViz). That’s fine: just make sure you always use the same Documents folder, the one you reach by clicking Documents in the sidebar.

2.2 Make file extensions visible

System Where to find the setting
Windows 11 In File Explorer, click View → Show → turn on File name extensions
Windows 10 In File Explorer, click the View tab → tick File name extensions
macOS In Finder, open the Finder menu (top left) → Settings (called Preferences on older versions) → Advanced → tick Show all filename extensions

From now on you will see data.RData instead of just data.

2.3 Make your browser ask where to save downloads

This is the most useful setting in this tutorial. If the browser asks where to save each file, you can save the data directly into the challenge folder and never have to move files around.

Can you skip this step? Yes, if you’re already comfortable finding, moving and organizing files and folders on your computer. The browser asking every time can get tiresome. If you skip it, use Option B in Step 2 of every challenge.

Browser Where to find the setting
Chrome Settings → Downloads → turn on Ask where to save each file before downloading
Edge Settings → Downloads → turn on Ask me where to save each file
Firefox Settings → General → Files and Applications → select Always ask you where to save files
Safari Settings → General → File download location → choose Ask for each download

2.4 Configure RStudio

  1. Open RStudio.
  2. Go to Tools → Global Options… → General.
  3. Untick “Restore .RData into workspace at startup”.
  4. Set “Save workspace to .RData on exit” to Never.
  5. Click OK.

Why? Otherwise RStudio remembers old objects between sessions. Your script may seem to work on your computer and still fail on the platform, which starts from nothing.

2.5 Install ggplot2

R comes with some basic tools, but ggplot2 is a package: an extension you add to R, like installing an app on your phone. You only install it once. After that, it stays on your computer.

  1. In RStudio, click on the Console (bottom left).

  2. Type this and press Enter:

    install.packages("ggplot2")

  3. Wait until the Console shows the > prompt again. You will see a lot of text; that’s normal. If R asks “Do you want to install from sources the packages which need compilation?”, type no and press Enter.

  4. Check that it works. Type this in the Console and press Enter:

    library(ggplot2)

    If nothing happens (no red error message), ggplot2 is installed.

Install once, load every time.

  • install.packages("ggplot2") downloads the package to your computer. Run it only once, in the Console. Never put it in your script.
  • library(ggplot2) loads the package so you can use it. It goes at the top of every script, every time.

If you get a new computer or reinstall R, you’ll need to install ggplot2 again.

3. Every challenge, step by step

Do these steps in this order for every challenge. The examples use challenge 01; replace the number with the current challenge.

Step 1: Create a new project

  1. In RStudio: File → New Project…
  2. Choose New Directory → New Project.
  3. Directory name: challenge-01
  4. Create project as subdirectory of: click Browse… and select your DataViz folder.
  5. Click Create Project.

RStudio restarts. Check two things:

  • The top-right corner of RStudio shows challenge-01.
  • The Files pane (bottom right) shows the challenge-01 folder with a challenge-01.Rproj file inside.

R is now standing in Documents/DataViz/challenge-01.

Step 2: Put data.RData inside the project folder

Option A (recommended): save it there when you download it

  1. Go to the challenge on the platform and click the link to download the data.
  2. The browser asks where to save the file (because of Section 2.3).
  3. Go to Documents → DataViz → challenge-01.
  4. Make sure the file name is exactly data.RData, then click Save.

Option B: move it from Downloads

Use this option if you skipped Section 2.3, or if the file went to your Downloads folder anyway.

Windows

  1. Open File Explorer and click Downloads in the left sidebar.
  2. Find data.RData. Right-click it → Cut (or select it and press Ctrl + X).
  3. Go to Documents → DataViz → challenge-01.
  4. Right-click an empty area → Paste (or press Ctrl + V).

macOS

  1. Open Finder and click Downloads in the left sidebar.
  2. Find data.RData and select it. Press Cmd + C.
  3. Go to Documents → DataViz → challenge-01.
  4. Press Option + Cmd + V. This moves the file instead of copying it.

Tip for both systems: you can also drag the file from one window to the other. Open two windows (Downloads and challenge-01) side by side and drag it across.

Watch out: if you downloaded the data more than once, the file may be called data (1).RData or data-2.RData. Rename it to exactly data.RData, and delete the extra copies.

Step 3: Check that R can see the data

Look at the Files pane in RStudio. You should see data.RData next to challenge-01.Rproj. If you don’t see it, click the circular arrow (refresh) in the Files pane.

You can also type this in the Console (bottom left) and press Enter:

file.exists("data.RData")
  • TRUE means R can see the file. You can continue.
  • FALSE means the file is not in the project folder. Go back to Step 2.

Step 4: Create your script and save it

  1. File → New File → R Script.
  2. Copy the template from Appendix A into the new script.
  3. Save it: File → Save (Ctrl + S on Windows, Cmd + S on macOS).
  4. RStudio proposes the project folder automatically. Name the file e.g. challenge-01.R and click Save. The platform doesn’t care about the script’s name, but using the same pattern every time will help you find your files.

The Files pane should now show three files: challenge-01.Rproj, data.RData and challenge-01.R.

Step 5: Work on your plot

Now write your code. Useful things to know:

  • To run one line or the selected lines: Ctrl + Enter (Windows) / Cmd + Enter (macOS).
  • To see which objects load() created, look at the Environment pane (top right), or run ls() in the Console.
  • Save often (Ctrl + S / Cmd + S). If the script’s name appears red with an asterisk, it has unsaved changes.

Step 6: Test your script like the platform will

The platform runs your script from the beginning, in an empty R session. Before you submit, do the same:

  1. Session → Restart R. This empties R’s memory.
  2. Click the Source button (top right of the script), or press Ctrl + Shift + S (Windows) / Cmd + Shift + S (macOS).

If there are no red error messages in the Console, your script works on its own.

Step 7: Find and check output.png

After running the script, output.png appears in the Files pane (refresh it if needed). Click it to open it and compare it with the target plot.

If you want to see the folder outside RStudio: in the Files pane, click the gear icon (called More in some versions) → Show Folder in New Window.

Step 8: Test and submit your script

Before uploading, go through the checklist in Section 5.

  1. In the Files pane, click the gear icon → Show Folder in New Window. Your challenge folder opens in File Explorer or Finder.
  2. Go to the platform in your browser and open the challenge’s upload page.
  3. Drag challenge-01.R from the folder window onto the upload area of the platform (upload the .R file, not the .Rproj, not data.RData, and not output.png).
  4. Click Test Script. The platform runs your script, which takes a little while. Wait for the result: don’t click again and don’t close the page.
  5. Look at the result on the screen. There are three possibilities:
    • Your script failed. For example, it has a syntax error, or it didn’t create output.png. The platform shows an error message explaining what went wrong. Read it carefully: it usually tells you what to fix. Section 4 lists the most common errors. Fix your script in RStudio, save it, and start again from point 3. Nothing has been submitted yet.
    • Your script worked, but the plot is not what you expected. Cancel, fix your script in RStudio, save it, and start again from point 3.
    • Your script worked and you are happy with the result. Confirm your submission.

Confirming is final. Once you confirm, your submission can’t be changed. You can test your script as many times as you want, so only confirm when you’re sure.

Step 9: Coming back to a challenge later

Always open the project, not the script:

  • Double-click challenge-01.Rproj in the challenge folder, or
  • In RStudio: File → Recent Projects → challenge-01.

Watch out: when you open RStudio normally, it reopens the last project you used. When you start a new challenge, that is probably the previous one. Always check the top-right corner of RStudio to make sure you are in the right challenge.

If you double-click the .R file instead, RStudio opens it outside the project. R won’t be standing in the right folder, and load("data.RData") will fail.

4. When things go wrong

What you see Why it happens How to fix it
cannot open file ‘data.RData’: No such file or directory R is not standing in the folder where data.RData is. Check the top-right corner shows your project. Check data.RData is in the Files pane. See Steps 2, 3 and 9.
could not find function “ggplot” ggplot2 is not loaded. Make sure library(ggplot2) is at the top of your script and that you ran it.
there is no package called ‘ggplot2’ ggplot2 is not installed on your computer. Run install.packages("ggplot2") in the Console, once. Never put it in your script.
object ‘xxx’ not found You’re using a name that doesn’t exist, or a line that creates it hasn’t been run. Run ls() after load() to see the real object names. Run your script from the top (Step 6).
The Console shows + instead of >, and nothing happens A parenthesis or a quote is not closed, so R is waiting for you to finish the command. Press Esc. Then check that every ( has its ) and every " has its partner.
Cannot use + with a single argument A line starts with +. In ggplot2, the + must go at the end of a line, not at the beginning of the next one. Move the + to the end of the previous line.
The plot is missing some layers, but there is no error A + is missing at the end of a line, so the next lines are not added to the plot. Every line of your plot except the last one must end with +.
Works in RStudio but fails on the platform Your script depends on something that was only in memory, or on a path that only exists on your computer. Do Step 6. Remove any setwd() and any path like C:/Users/... or /Users/....
The file is called data (1).RData You downloaded it more than once. Rename it to data.RData and delete the duplicates.
The platform shows an error after Test Script Your script failed: a syntax error, a missing object, or no file called exactly output.png was created. Read the error message. Reproduce it with Step 6, fix it, and upload again. Nothing was submitted, so you can retry.
I can’t find output.png It’s in the project folder, but you’re looking elsewhere. Refresh the Files pane. Use gear icon → Show Folder in New Window.
output.png looks different from what I see in RStudio The Plots pane has a different size than the saved image. Always check output.png itself, not the Plots pane. The size is set in ggsave().
RStudio’s top-right corner says Project: (None) You opened the script without opening the project. Open the .Rproj file (Step 9).
I see data but not data.RData Extensions are hidden. Section 2.2.

5. Checklist before submitting

Appendix A: Script template

# Challenge XX
# Name: Your Name

# 1. Load packages ------------------------------------------------------
library(ggplot2)

# 2. Load the data -----------------------------------------------------
load("data.RData")

# 3. Build the plot ----------------------------------------------------
ggplot(...) # + will add more things

# 4. Save the plot -----------------------------------------------------
ggsave("output.png") # options like width and height will be important

Rules for your script:

  • The image must be called exactly output.png: lowercase, no spaces, .png extension. The platform looks for that name, so Output.png, plot.png or output.jpg count as no plot at all.
  • Never use setwd(). The project already puts R in the right folder, and the platform has its own folders.
  • Never write full paths like C:/Users/anna/.... They only exist on your computer.
  • Never put install.packages() in the script. Install packages once from the Console.
  • The script must work from top to bottom in an empty R session (Step 6).

Appendix C: Glossary

  • Console: the bottom-left pane of RStudio, where you type commands and see results and errors.
  • Environment pane: the top-right pane; it lists the objects R currently has in memory.
  • Extension: the letters after the last dot in a file name (.R, .png…). They tell you the file type.
  • Files pane: the bottom-right pane; it shows the contents of the folder where R is standing.
  • Folder (directory): a container for files and other folders.
  • Package: an extension that adds new functions to R, like ggplot2. You install it once (Section 2.5) and load it with library() in every script.
  • Path: the address of a file: the folders you open to reach it.
  • Project: a folder with a .Rproj file. Opening it makes R stand in that folder.
  • Script: a .R file containing your code.
  • Source: to run a whole script from top to bottom.
  • Working directory: the folder where R is standing. load() and ggsave() read and write there. See Section 1.4.
